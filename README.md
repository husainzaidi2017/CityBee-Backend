# CityBee API

NestJS backend for the CityBee local-discovery platform.
Flutter app → NestJS API → Supabase Postgres (PostGIS) + Cloudinary.

## Architecture

```
Flutter (city-bee/)
   │  HTTPS REST, Supabase Auth JWT in Authorization header
   ▼
NestJS API (this project)  ←─ citybee_api DB role (BYPASSRLS, least privilege)
   ├── Supabase PostgreSQL + PostGIS   (data + geo queries)
   ├── Supabase Auth                   (JWT verification via /auth/v1/user)
   └── Cloudinary                      (signed image uploads; API secret server-side only)
```

- **Database access**: direct Postgres via the Supavisor session pooler using
  the dedicated `citybee_api` role (created in the project; password in `.env`).
  All queries use postgres.js tagged templates — every value is parameterized.
- **RLS**: public tables have Row Level Security policies for direct-client
  access (anon key). The API role bypasses RLS; ownership checks are enforced
  in the service layer.
- **Images**: Cloudinary folder strategy `citybee/{businesses|offers|places|profiles}/{id}/`.
  Supabase stores only `image_url` + `public_id` — never binaries.

## Modules

| Module | Endpoints |
|---|---|
| health | `GET /api/health` |
| auth | `GET /api/auth/me` |
| users | `GET /api/users/me`, `PATCH /api/users/me` |
| categories | `GET /api/categories`, `GET /api/categories/:id` |
| cities | `GET /api/cities`, `GET /api/cities/:id`, `POST /api/cities/from-places` |
| businesses | `GET /api/businesses`, `GET /api/businesses/nearby`, `GET /api/businesses/search`, `GET /api/businesses/:id` |
| offers | `GET /api/offers`, `GET /api/offers/nearby`, `GET /api/offers/count`, `GET /api/offers/:id` |
| doctors | `GET /api/doctors` (+nearby/search/:id) — business kind `doctor` |
| restaurants | `GET /api/restaurants` (+nearby/:id) — business kind `restaurant` |
| hotels | `GET /api/hotels` (+nearby/:id) — business kind `hotel` |
| places | `GET /api/places`, `GET /api/places/nearby`, `GET /api/places/search`, `GET /api/places/:id` |
| reviews | `GET /api/businesses/:id/reviews`, `POST /api/businesses/:id/reviews` |
| favorites | `GET /api/favorites`, `POST /api/favorites`, `DELETE /api/favorites/by-entity`, `DELETE /api/favorites/:id` |
| notifications | `GET /api/notifications`, `PATCH /api/notifications/:id/read`, `PATCH /api/notifications/read-all` |
| uploads | `POST /api/uploads/image`, `POST /api/uploads/images`, `POST /api/uploads/associate` |

Public routes are marked `@Public()` (guest browsing). Everything else
requires a valid Supabase JWT. Swagger UI: `http://localhost:3000/api/docs`
(non-production only).

## Response envelope

```json
{ "success": true, "data": {}, "message": "Success", "pagination": { "page": 1, "limit": 20, "total": 42, "hasNext": true } }
```

Errors: `{ "success": false, "message": "user-safe text", "statusCode": 4xx }`.

## Nearby queries (PostGIS)

`GET /api/businesses/nearby?lat=28.8386&lng=78.7733&radius=3000` runs
`ST_DWithin(location, ST_SetSRID(ST_MakePoint(lng, lat), 4326)::geography, radius)`
ordered by `location <-> point` using a GIST index. Longitude comes first
in `ST_MakePoint`.

## Setup

```bash
npm install
cp .env.example .env   # fill in values
npm run start:dev
```

### Environment variables

| Variable | Purpose |
|---|---|
| `PORT` | HTTP port (default 3000) |
| `CORS_ORIGINS` | comma list; `*` for dev |
| `SUPABASE_URL` | project URL |
| `SUPABASE_ANON_KEY` | publishable key (JWT verification) |
| `SUPABASE_DB_URL` | Postgres connection string (citybee_api role via pooler) |
| `SUPABASE_SERVICE_ROLE_KEY` | optional (auth-admin ops only) |
| `CLOUDINARY_CLOUD_NAME/API_KEY/API_SECRET` | signed image uploads |
| `GOOGLE_MAPS_SERVER_KEY` | optional server-side Places/geocoding |

Never commit `.env`. The Flutter app receives **no** service-role key and
**no** Cloudinary secret — only the publishable Supabase keys and the API
base URL (`--dart-define=API_BASE_URL=...`).

## Database role

The API does not use the `postgres` superuser. A least-privilege role was created:

```sql
create role citybee_api login password '<generated>' bypassrls;
grant usage on schema public to citybee_api;
grant select, insert, update, delete on all tables in schema public to citybee_api;
```

Connection string uses the Supavisor session pooler:
`postgresql://citybee_api.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`

## Deployment notes

- Vercel serverless does not suit this long-lived NestJS process (pg
  connection pools, warm request patterns). Deploy to a container host
  (Railway/Render/Fly/Cloud Run) or a VPS; use the transaction pooler
  (port 6543) if functions-based hosting is forced later.
- Set the env vars above in the host; point Flutter builds at the deployed
  URL with `--dart-define=API_BASE_URL=https://api.<domain>/api`.
- Swagger is disabled automatically in production.

## Bulk import (design)

`businesses.external_ref` (and `places.external_ref`) store stable
import IDs so CSV/Excel imports can upsert deduplicated business + doctor
rows, upload images to Cloudinary `citybee/businesses/{id}/`, and create
`business_images` rows without manual URL pasting.
